# v0.6.10 — Dependency security fixes and spec refresh

Patch on top of [v0.6.9](https://github.com/roxelfivan/apeditor/releases/tag/v0.6.9). No user-visible behaviour changes — this release clears the outstanding `npm audit` findings, records install-script approvals, and brings the Functional Specification back in line with the code.

## Security

`npm audit` reported **4 vulnerabilities (3 moderate, 1 high)** on v0.6.9. All four are now fixed and `npm audit` reports **0 vulnerabilities**.

| Package | v0.6.9 | v0.6.10 | Advisory |
|---|---|---|---|
| `vite` | 5.4.21 | **6.4.5** | `GHSA-4w7w-66w2-5vf9` (path traversal in optimized deps `.map` handling), plus the `launch-editor` command-injection advisories |
| `esbuild` (via Vite) | 0.21.5 | **0.25.12** | `GHSA-67mh-4wv8-2f99` — dev server readable by any website |
| `uuid` | 9.0.1 | **11.1.1** | `GHSA-w5hq-g745-h8pq` — missing buffer bounds check in `v3` / `v5` / `v6` |
| `postcss-selector-parser` | 6.1.4 | **6.1.5** | `GHSA-rj75-hqrm-r3gf` — quadratic complexity in flat selector parsing |

### Notes

- The `uuid` bump keeps the `v4` API and the import sites unchanged. The `@types/uuid` stub was removed — `uuid@11` ships its own type declarations.
- `vite@6` is compatible with the pinned `@vitejs/plugin-react@4.3.1` (peer range `^4.2.0 || ^5 || ^6 || ^7`).
- `postcss-selector-parser` is now an explicit devDependency so the patched version is pinned rather than inherited from Tailwind's range.

## Install scripts

npm blocks dependency lifecycle scripts by default and reports the packages it skipped. Three were pending review, and all three are now approved in `package.json`:

| Package | Script | Why it is safe |
|---|---|---|
| `esbuild` | `postinstall: node install.js` | Downloads/validates the platform binary for the esbuild version being installed. |
| `fsevents` | `install` | Builds the macOS native file-watcher. Optional — used by Vite and Tailwind for fast file watching on macOS. |
| `protobufjs` | `postinstall: node scripts/postinstall` | Reads the parent `package.json` and warns about the version scheme. No network, no writes. |

Approvals are recorded **by name, not by pinned version**, so they survive future dependency upgrades instead of silently going stale.
