# v0.6.14 — Fix Write-panel selection drift at document bottom

Patch on top of [v0.6.13](https://github.com/roxelfivan/apeditor/releases/tag/v0.6.13). Selecting or editing near the bottom of a document that ends with a newline no longer misaligns the caret / selection band from the visible words.

## Root cause

The Write pane paints words on a `.cm-mirror` overlay behind a transparent `<textarea>`. A textarea renders a final `\n` as an empty extra line; a `white-space: pre-wrap` div drops that hanging segment break. The mirror was therefore one line-height shorter than the textarea, so at max scroll `mirror.scrollTop = ta.scrollTop` clamped and the visible words drifted above the native selection.

## Fix

`CommentLayer` appends a trailing `<br>` when `content` ends with `\n`, restoring line-count parity. The `<br>` adds no text node, so comment / selection offset mapping stays byte-exact to the document.

## Verification

- `npm run typecheck` — clean.
- `npm run build` — clean.
- Manual check: trailing-newline docs → equal `scrollHeight`; at bottom → `scrollTop` diff `0`.
