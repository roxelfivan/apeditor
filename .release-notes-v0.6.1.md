# v0.6.1 — Format menu, Split = Write/Preview | Graph

Patch on top of [v0.6.0](https://github.com/roxelfivan/apeditor/releases/tag/v0.6.0). Three user-facing fixes share this patch: the Format dropdown was clipped by the one-row toolbar; Split is redefined as Write/Preview on the left with Graph on the right; and Graph node clicks scroll the Write pane to the selected passage (keeping the mirror layer in sync). No new dependency, no store-schema change, no migration.

## Fixed

### Format dropdown clipped by the toolbar scroller

The editor toolbar is a horizontal scroller (`overflow-x: auto` on `[data-editor-toolbar-scroll]`). Per the CSS overflow rules, setting one axis to a non-`visible` value forces the other axis to compute as `auto` as well — so overflowing children are clipped on **both** axes.

The Format menu was `position: absolute` inside a `relative` trigger wrapper that lives inside that scroller. Measured before the fix: the menu laid out ~145 px tall starting a few pixels below a ~32 px-tall scroller, so the entire panel sat outside the clip rect. Accessibility still exposed the menuitems; hit-testing and the eye did not.

**Fix.** The menu panel is now `position: fixed`. A `useLayoutEffect` (keyed on `formatMenuOpen`) anchors `left` / `top` to the trigger button's `getBoundingClientRect()`, prefers below the button, flips above when there is not enough room, and clamps both edges to the viewport with an 8 px pad. It re-applies on `resize` and capture-phase `scroll` so a sideways toolbar scroll cannot leave the panel stranded.

This matches the contract already used by `FileActionsButton` and the Graph Filter from the same toolbar. The trigger wrapper keeps `data-format-menu` for the outside-click closer; only the panel escapes the clipping ancestor.

### Graph node click did not scroll the Write pane into view

`mvp:select-range` always restored the caret with `preserveScroll: true`, so a heading click set the selection but left `scrollTop` where it was — the highlight could sit off-screen. Graph-driven events now pass `scrollIntoView: true`; `restoreCaret` measures the offset with a wrap-matched probe and scrolls the textarea so `start` sits near the top quarter of the viewport. Apply / Chat keep the previous scroll behaviour.

Visible words live on `.cm-mirror` (the textarea text is transparent). Programmatic scroll must set the mirror's `scrollTop` too, or only the selection rectangle moves. The scroll-sync effect also rebinds when `splitLeftMode` remounts the textarea inside Split without changing `viewMode`.

## Changed

### Split = Write/Preview | Graph

Split used to be Write left + Preview right. It is now:

- **Left:** Write or Preview, switched by a tablist on that pane (`layout.splitLeftMode`, persisted, default `'write'`)
- **Right:** Graph (same `GraphView` as full Graph mode)

Standalone Write / Preview / Graph stay full-pane. The view-mode `<select>` order is **Write → Preview → Graph → Split**.

`showWriteTools` follows the Write pane (Format / Comment / Predict). `GraphViewControls` mount whenever Graph is visible (Split or Graph). A heading / term click from full Graph opens Split with left Write; from Split with Write already open, `viewMode` stays put.
