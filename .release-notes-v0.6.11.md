# v0.6.11 — Compare overlay: side-by-side document view + resize

Patch on top of [v0.6.10](https://github.com/roxelfivan/apeditor/releases/tag/v0.6.10). The Compare popup now shows the whole document in order — unchanged text keeps its place among the changes — and the panel is resizable from its left edge.

## Compare overlay

| Before (v0.6.9 / v0.6.10) | After (v0.6.11) |
|---|---|
| Fixed-width card stack of changes only | Side-by-side **Original \| Revised** document view |
| Unchanged text was invisible | Unchanged runs sit between change cards, in document order |
| Panel width was a fixed `max-w-md` | Left-edge resize, persisted as `layout.compareWidth` (360–900, default 560) |

- Each pending change is still a full `ProposedEditCard` (Apply / Skip), sized to fill the panel so stored chat-card pixel sizes cannot overflow.
- Card previews show only the hunk itself; neighbouring context used for unique Apply anchors stays in the unchanged rows above/below (no duplicated lines).
- Skipped hunks (no unique span) remain visible as muted rows with a short note.
- Per-card Apply now updates the panel’s remaining count and swaps the card for an **Applied** row (previously Apply all stayed inflated after a single Apply).

## Diff engine

`compareToProposedEdits` now returns `segments` alongside `edits` / `skippedHunks`: an ordered walk of `unchanged` | `change` | `skipped` that reconstructs both documents. Change segments carry the raw hunk text; edits still carry the expanded unique anchor for Apply.
