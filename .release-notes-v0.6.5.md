# v0.6.5 — Debug token counter, single-send comment batches

Patch on top of [v0.6.4](https://github.com/roxelfivan/apeditor/releases/tag/v0.6.4). Adds a Debug Mode token counter next to both send buttons so you can see how big the next request is — and whether the Local Model has room for a full reply — before sending. Also fixes the comment batch and rejection sends, which were transmitting the message body twice.

## Added

### Debug Mode token counter

- **Chat panel** — next to **Send**, an estimate of what the next message will cost, plus `sent ~N` for the previous send.
- **Comment tray** — next to **Send to AI**, an estimate of the next comment batch.
- Only visible when **Debug Mode** is on (Settings).
- The count is measured against the **real packed request**, not the length of the typed text. `buildRequestPreview` calls the same `buildRequestMessages` the real send uses, so it includes the document outline (or the full body on Local Model), the `@`-referenced docs, the comment batch, and the selection context.
- Rough estimate, about **4 characters per token** — no tokenizer dependency, no extra compute. CJK characters count as ~1 token each.
- On the Local Model the pill shows the budget too: **8,192** tokens total, **1,024** reserved for the reply, so about **7,168** for the prompt. It turns **amber** above 90 % of that and **red** above it, with a tooltip explaining that the reply will be cut short. Minimax / OpenAI have no local limit, so they show the size without a budget check.

### Local Model budget constants

`LOCAL_MAX_NUM_TOKENS` (8192) and `LOCAL_MAX_OUTPUT_TOKENS` (1024) are now exported from `src/api/localGemma.ts` and used by the runtime itself, so the counter and the engine cannot drift apart.

## Fixed

- **Comment batches were sent twice.** The comment **Send to AI** path and the staged-rejection path both read the chat history *after* appending the user message, then appended it again in the outbound array. The model saw the whole batch (or rejection body) twice — doubling the prompt size, which on the Local Model path is enough to blow the 8192-token KV cache. The bug was invisible in the UI because the chat bubble renders normally. Both paths now snapshot the history correctly; `runAssistantReplyAfterCommit` no longer takes the user message as a parameter.
